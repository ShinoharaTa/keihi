# keihi 要件 v2（2026-11-05 言語化完了・2026-11-06 P1/P3 の大部分を feature/cashflow で実装）

前回計画（mvp-plan.md v2 = freee + 証憑入口）に対し、ユーザーの本質的な目的を聞き直して再整理したもの。
本書は**確定事項と未決を分けて**書く。実装・issue・commit はこの後に別途決める。
関連: research-cashflow-sources.md（取得元の調査）、design-diff-v2.md（旧決定との差分。MF 向けの項目は不要になった）、current-system.md（現行実装の見取り図）。

## 1. 本質（ユーザーの言葉）

> 口座・カード・PayPay の利用も含めて資金の流れを**すべて可視化**し、**3 年以内の近い資金の動き**（税金・保険・車検など）を把握して、月末に向けていくら残すか・無駄遣いしていないかを分かるようにしたい。
> そのうえで、経費にするものを会計サービスに預ける。keihi は **MCP** として実装し、経費登録や領収書の処理は **self agent から投げられる**ようにする。

## 3. 要件

### R-A 明細の取り込み
- A1. freee の口座連携済みの全口座について `wallet_txns` を日次で取得し、`bank_txns`（仮）に統一形式で保存する（取得元・外部 ID・日付・金額・摘要・口座・残高）。
- A2. CSV インポート: PWA からのアップロード／self agent から MCP でファイルを渡す／サーバーのフォルダ監視（経路は未決 V3）。パーサーは取得元ごとに追加できる構造。
- A3. 重複排除: 同一口座が API と CSV の両方から来ても 1 件にする（外部 ID → 日付+金額+摘要の近似）。
- A4. 口座間振替（自分の口座同士の移動）を検出し、収支集計から除く。
- A5. 取得状況（口座ごとの最終同期・最終 CSV 取り込み日・エラー）を記録し、Web UI と `/api/status` で見せる。

### R-B 可視化（Web UI）
- B1. 月次の収支サマリ（口座別・カテゴリ別・事業/私用別）。使っている口座（active=1）の明細だけを数える。
- B2. 明細一覧（期間・口座・タグ・金額・摘要で検索）。既定は使っている口座（active=1）の明細だけ。
- B3. 事業/私用タグ: ルール（取引先辞書を流用）+ エージェント提案 + 手動。
- B4. 証憑との照合状態（明細 ⇔ 領収書 ⇔ freee の取引）。
- B5. 取り込み状況（A5）。
- B6. 資金繰り表（R-D）。

### R-C 経費登録・領収書処理（MCP 中核）
- C-1. 既存の領収書パイプライン（撮影 → 即アップロード → Gemini 抽出 → 確認カード → freee 取引 → 照合）を流用（current-system.md §2）。
- C-2. MCP ツール: 領収書の投入（画像/PDF）、確認カードの取得、確定（approve / personal / duplicate / reject）、要対応の一覧と解消、明細の読み取り、月次集計の読み取り、資金繰り表の読み取り。
- C-3. 明細 ⇔ 領収書の照合: カード明細に対応する領収書が無い経費を「領収書待ち」として一覧化（C8 により領収書なしでは経費にしない）。
- C-4. 実行主体を監査ログに残す（`field_sources` の `agent` を使う）。

### R-D 将来の資金の動き（3 年）
- D1. 予定支出の台帳: 名称・金額・期日・周期（毎月/隔月/毎年/隔年）・口座・分類（税金/保険/車/その他）。
- D2. 周期検出: 過去明細から「同じ相手に同額が周期的」を検出し、台帳への登録を提案（C11）。
- D3. 資金繰り表: 現在残高 + 予定収入 − 予定支出 → 36 か月分の月末推定残高。「月末に残す額」の目安を出す。
- D4. 期日通知: 期日 N 日前に PWA / MCP で知らせる（経路は未決 V4）。
- D5. 税額の概算（段階 2、C12）: 今年の損益から所得税・住民税・国保・個人事業税を概算して D3 に流す。
