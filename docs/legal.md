# 経費精算ツール（入口自作 + MF/freee 送信）法令調査ドラフト

- 調査日: 2026-10-13（法令・資料は同日時点で取得できた版。R8.7 版 電帳法一問一答を一次資料の中心に使用）
- 本書は税理士の助言ではない。「事実」は出典 URL つき、**[推測]** は筆者の解釈、**[要確認]** は未検証事項。
- 前提: 個人事業主・青色申告・暦年。基準期間（前々年）売上高 5,000 万円以下を想定。

## 0. 結論サマリ（先に読む）

1. **最終保存先を MF または freee に置く構成は、法令上成立し得る。** 両社とも JIIMA のスキャナ保存・電子取引・電子帳簿の各認証を取得済み（§2.1）。ただし JIIMA 認証は「機能要件」だけであり、**入力期限・規程の備付け・検索項目の入力などの運用要件は利用者（＝自作ツール + 本人）が満たす**。
2. **一番の論点は「API で上げたファイルが、スキャナ保存の証憑として扱われるか」。**
   - MF: 仕訳 ID なしで API アップロードすると「電子取引データ保存」扱いになると公式に書かれている。スキャナ保存扱いにするには仕訳 ID を付けるか UI 側の設定が必要。API でタイムスタンプが付くかは書かれていない → **[要確認・実機テスト必須]**
   - freee: API で発行元・発行日・金額（検索項目）を渡せる。スキャナ／電子取引の区分を指定するフィールドは無い。タイムスタンプは使わず、変更履歴で真実性を担保する方式（2022-01-17 にタイムスタンプ機能を終了）。
3. **スキャナ保存は「受領からおおむね 7 営業日以内」（規程を作れば最長 2 か月 + 7 営業日）に、MF/freee 側へ格納するまでを終える必要がある。** 自作側で人の確認待ちのまま止めると期限を超える。→ **撮影したら即アップロードし、分類・仕訳はあとから**、という順にするのが安全。
4. **自作のサーバだけではタイムスタンプの代わりにならない**（一問一答 スキャナ 問32）。自作側を正式な保存先にするなら、総務大臣認定のタイムスタンプが要る。→ 正式な保存先は MF/freee、自作側は控え、と割り切るのが妥当。
5. **紙原本は、要件を満たして入力期間内に保存し、同等確認をすれば即時廃棄してよい**（スキャナ 問3）。期限を過ぎたものは紙も保管する。
6. **解約後の 7 年保存**: freee は「アカウントと事業所を残して、ファイルボックス上で保存せよ。ダウンロードしたファイル単体では要件を満たさない」と明記。MF は解約後も閲覧・ダウンロードできると FAQ にある。他サービスへの移行は、タイムスタンプ代替の証明情報まで引き継ぐ必要があり、個人には現実的でない（スキャナ 問64）。→ **保存期間中はアカウントを残す前提で計画する。**
7. **青色申告特別控除**: 令和8年分（2027-03 申告）は 65 万円（複式簿記 + e-Tax）。**令和9年分からは 75 万円 / 65 万円 / 10 万円 の3段階**で、書面申告は 10 万円。75 万円には「優良な電子帳簿（その年の 1/1 から）+ 届出」または「デジタルシームレス保存」が必要。

## 1. 電子帳簿保存法の整理

### 1.1 3区分

| 区分 | 対象 | 義務か任意か | 本ツールでの該当 |
|---|---|---|---|
| 電子帳簿等保存 | 自分が PC 等で作った帳簿・書類 | 任意 | MF/freee の仕訳帳・総勘定元帳 |
| スキャナ保存 | 紙で受け取った・渡した書類（決算関係書類は対象外） | 任意 | 紙の領収書のスマホ撮影 |
| 電子取引データ保存 | メール・Web・EC・クラウドで授受した取引情報 | **法人・個人事業者は対応が必要** | メール添付 PDF、EC の領収書、カード明細など |

出典: 国税庁 R8.6 パンフ https://www.nta.go.jp/law/joho-zeikaishaku/sonota/jirei/tokusetsu/pdf/0026006-122.pdf

- スマホやデジカメも「スキャナ」に含まれる（スキャナ 問5、取扱通達4-16）。私物の端末でもよい（同 問6）。
- 電子取引データを印刷した紙をスキャナ保存しても認められない（スキャナ 問65）。**PDF や EC の領収書は、電子データのまま保存する。**
- EC サイトの領収書は、サイト上で確認できるようになった時点で授受があったとされる。ダウンロードしていなくても保存義務はある（電子取引 問44）。

### 1.2 スキャナ保存の要件（令和6年1月1日以後の保存分）

出典: スキャナ 問10 の要件表、パンフ「はじめませんか、書類のスキャナ保存」 https://www.nta.go.jp/law/joho-zeikaishaku/sonota/jirei/tokusetsu/pdf/0023006-085_03.pdf

| 要件 | 重要書類（領収書・請求書・契約書・納品書） | 一般書類（見積書・注文書等） |
|---|---|---|
| 入力期間 | 早期入力方式: 受領後おおむね 7 営業日以内／業務処理サイクル方式: 最長 2 か月 + おおむね 7 営業日（**各事務の処理規程がある場合のみ**） | 期間制限なしも可（事務手続書類の備付けが条件） |
| 解像度 | 200dpi 相当以上 | 同左 |
| 階調 | RGB 各 256 階調以上（24bit カラー） | グレースケール可 |
| タイムスタンプ | 入力期間内に総務大臣認定タイムスタンプを付ける。**入力期間内に保存したことを確認できるシステムなら代替可** | 同左 |
| ヴァージョン管理 | 訂正・削除の事実と内容を確認できるシステム、または訂正・削除できないシステム | 同左 |
| 帳簿との相互関連性 | 必要 | 不要 |
| 見読可能装置 | 14 インチ以上のカラーディスプレイ、カラープリンタ、操作説明書。4 ポイント文字を認識できる状態で速やかに出力 | グレースケールなら白黒機でも可 |
| システム概要書等 | システム概要書・仕様書・操作説明書・手順と担当を示した書類の備付け（規則2⑥六、2②一） | 同左 |
| 検索 | ①取引年月日・金額・取引先で検索 ②日付・金額の範囲指定 ③2項目以上の組合せ。**ダウンロードの求めに応じられるなら②③は不要**（①は残る） | 同左 |

令和5年度改正（令和6年1月1日以後の保存分）で不要になったもの: 解像度・階調・大きさの情報の保存、入力者等情報の確認。相互関連性は重要書類だけに縮小（スキャナ 問10 注5、問27）。
出典: R5 改正の概要 https://www.nta.go.jp/law/joho-zeikaishaku/sonota/jirei/pdf/0023003-082.pdf

ポイント（一問一答より）:
- **問21**: 入力期間内にやるべきことは、撮影だけでなく、タイムスタンプを付けた状態、または訂正削除履歴が残るシステムに格納した状態にすること。**検索項目と相互関連性は「入力」に含まれない**。保存時点で帳簿がまだ無ければ、決算終了後遅滞なく満たせばよい。
- **問22**: 7 営業日に間に合わないやむを得ない事情があれば、解消後すぐ入力すれば「速やか」と扱われる。
- **問26**: スマホの解像度は「書類の大きさ × 画素数」で判断する。A4 なら 2,338×1,654 px（約 387 万画素）以上。Exif の 72dpi 表示は解像度ではない。階調は Exif の BitsPerSample「8 8 8」で確認できる。
- **問27**: JPEG/TIFF/PDF のプロパティに残る解像度・画素数で、あとから要件を確認できる。
- **問31・32**: 訂正削除履歴が残るシステムに保存しただけでは、タイムスタンプの代わりにならない。時刻証明機能（NTP 同期など、保存時刻が改ざんされないことの客観的な担保）が要る。**自社システムでは原則この代替を満たせない**。他社にサービスとして提供しているベンダーのクラウドは例外的に認められる。
- **問37・38**: 4 ポイント文字が認識できれば圧縮保存してよい。テストチャートが無い場合は「200dpi 以上・24bit・非圧縮または可逆圧縮」なら認識できるとみなす。
- **問41**: OCR でテキスト化できなくても、日付・金額・取引先を手入力するなどして検索できるようにする。
- **問43**: 検索用の金額は、帳簿の経理方式に合わせるのが基本。書類記載の金額でも差し支えない。
- **問59**: 要件を満たさない電子データは保存書類として扱われない。紙原本が無ければ、仕入税額控除の否認や青色承認取消しの可能性がある。
- **問3**: 入力期間内に保存し、同等確認（折れ・欠けの確認を含む）をしたら紙は即時廃棄可。入力期間を過ぎたものは紙も保存する。
- 事務処理規程・規程サンプル: https://www.nta.go.jp/law/joho-zeikaishaku/sonota/jirei/0021006-031.htm

### 1.3 電子取引データ保存の要件

出典: 電子取引 問18・19・21・43・51、パンフ（R6.11） https://www.nta.go.jp/law/joho-zeikaishaku/sonota/jirei/tokusetsu/pdf/0024011-003_01.pdf

- **真実性（次のいずれか1つ）**
  1. タイムスタンプが付いたデータを受け取る
  2. 受け取ったあと、速やかに（またはサイクル後速やかに。後者は規程が必要）タイムスタンプを付ける
  3. 訂正削除履歴が残るシステム（または訂正削除できないシステム）で、**授受と保存の両方**を行う
  4. 「正当な理由がない訂正及び削除の防止に関する事務処理規程」を定め、備え付け、運用する
- **問43（重要）**: メールで受け取った PDF を、あとから訂正削除履歴の残るシステムに保存しても、授受がシステム外なので措置3 にはならない。措置4（事務処理規程）などが別途必要。
- **可視性**: 見読可能装置（PC・スマホ・プリンタ。プリンタは近所の有料機で代用可＝問21）。システム概要書（自社開発プログラムを使う場合だけ）。検索要件。
- **検索要件が不要になる場合**: ①基準期間（個人は前々年）の売上高が 5,000 万円以下で、ダウンロードの求めに応じられる場合。②出力した書面を日付・取引先ごとに整理して提示でき、かつダウンロードの求めに応じられる場合（問19・51）。ただし R7 改正の「デジタルシームレス保存」や 75 万円控除の要件は別。
- **猶予措置（令和6年1月以後）**: 税務署長が「相当の理由」を認め、かつデータのダウンロードと出力書面の提示の両方に応じられれば、データを保存しておくだけでよい。事前の届出は不要。
- **2023年末まで**の宥恕措置（紙に印刷して保存すれば可）は終了済み。

### 1.4 2026年時点の新しい改正

- **令和7年度改正（デジタルシームレス保存）**: Peppol（JP PINT / JP Self-Billing）のデジタルインボイス、または預貯金口座の決済データを、基準に適合するシステムで授受・保存し、帳簿と自動連携する仕組み。届出をすると、重加算税 10% 加重の適用除外（令和9年1月1日以後に法定申告期限が来る国税から）と、75 万円控除（令和9年分以後）の対象になる。
  出典: https://www.nta.go.jp/law/joho-zeikaishaku/sonota/jirei/pdf/0025003-097_01.pdf 、届出書 https://www.nta.go.jp/law/joho-zeikaishaku/sonota/jirei/0026001-065_01.htm
- **JIIMA の「デジタルシームレスソフト法的要件認証」は令和8年1月に開始**（スキャナ 問61）。2026-10-13 時点の認証一覧に MF・freee は無い（TKC 等のみ）。 https://www.jiima.or.jp/certification/digitalseamless/list/
- **令和8年度改正（青色申告特別控除の見直し）**: §3 を参照。電帳法の規則5条の項番号が令和9年から変わる（一問一答で「令和8年12月31日までは規則第5条第5項」と注記）。
- 届出書様式の通達改正（令和8年9月24日以後）は、システム更改に伴う様式整備で、要件自体の変更ではない。 https://www.nta.go.jp/law/tsutatsu/kobetsu/sonota/kaiseir0802xx/index2.htm

### 1.5 保存期間（個人・青色）

出典: スキャナ 問9 の表（R8.7）

| 種類 | 期間 |
|---|---|
| 帳簿（仕訳帳・総勘定元帳・現金出納帳・経費帳・固定資産台帳など） | 7年 |
| 決算関係書類（損益計算書・貸借対照表・棚卸表など） | 7年（問9 の表をPDFから読み取った値。表の崩れがありうるので [要確認]） |
| 現金預金取引等関係書類（領収証・小切手控・預金通帳・借用証など） | 7年（**前々年分の事業所得と不動産所得の金額が 300 万円以下なら 5 年**） |
| その他の書類（請求書・見積書・契約書・納品書・送り状など） | 5年 |
| **消費税の課税事業者**: 仕入税額控除の要件として保存する請求書等、自分が交付した適格請求書の写し | 上記にかかわらず **7年** |

- 起算日: 帳簿は閉鎖日の属する年の翌年 3/15 の翌日、書類は作成・受領日の属する年の翌年 3/15 の翌日から。
- 電子データ（スキャナデータ・電子取引データ）も同じ期間保存する（スキャナ 問9、電子取引 問17）。
- **[推測]** 実装上は、種類を区別せず一律に「年分の翌年 3/16 から 7 年」で保持するのが安全で簡単。

### 1.6 優良な電子帳簿

出典: R8.6 パンフ（上記）、帳簿 一問一答 問7 の要件表
- 要件: 訂正・削除・追加の履歴が残ること、帳簿間の相互関連性、日付・金額・相手方での検索（範囲指定・組合せを含む。ダウンロードの求めに応じる場合の緩和あり）、加えてシステムの説明書やディスプレイなどの備付け。
- 効果: その帳簿に関連する過少申告があったとき、**過少申告加算税が 10% から 5% に軽減**される（**課税期間の初日から**優良な電子帳簿として保存し、あらかじめ届出が必要）。令和9年分以後は 75 万円控除のルートの一つにもなる。
- 対象帳簿は仕訳帳・総勘定元帳・その他必要な帳簿（R5 改正で範囲が限定された）。

### 2.2 MF（クラウド確定申告 + クラウドBox）

事実:
- API でアップロードした証憑はクラウドBox に保存される。電帳法準拠の保存なので削除不可（ゴミ箱へは移せる）。1 件 5MB まで、1 仕訳あたり 5 件まで。**解像度などスキャナ保存要件を満たしていなくてもアップロードできてしまう**。要件を満たしているかは API の応答では返らず、画面で確認する。
- **仕訳 ID なしでアップロードすると「電子取引データ保存」の証憑として扱われる**。検索要件を満たすには、Box の画面で取引日・取引先・金額を入力するか、会計画面で仕訳に紐付ける。仕訳 ID 付きは「クラウド会計の仕様に準拠」。
  出典: https://developers.api-accounting.moneyforward.com/specs/vouchers
- API の対象は「クラウド会計・確定申告をご利用中のお客さま」。2026-03 提供開始、2026-09-24 に API キー認証を追加。技術サポートは士業の公認メンバーに限定。 https://biz.moneyforward.com/support/account/?p=57495
- クラウド確定申告のスキャナ保存: 事業者設定で「スキャナ保存機能を利用する」をオンにする。証憑添付機能で添付すると Box にタイムスタンプ付きで保存される。200dpi・24bit の判定チェックとアラートがある。期限は規程なしで 7 営業日、規程ありで 2 か月 + 7 営業日。取引先は仕訳の摘要（または取引先設定）に入れる。仕訳の「取引No.」で相互関連性を持たせる。「スキャナによる電子化保存規程」は利用者が作る。
  出典: https://biz.moneyforward.com/support/tax-return/guide/e-book/tr-eb07.html
- Box の「アップロード」、会計・確定申告の「証憑添付」で保存すると、電子取引にタイムスタンプが付く。そのため事務処理規程は不要（MF FAQ）。 https://biz.moneyforward.com/support/box/faq/ebq/ebq03.html
- 電帳法区分の変更可否（区分未設定 → スキャナ／電子取引には変更可、逆は不可など）。**API 経由の初期区分は記載なし**。 https://biz.moneyforward.com/support/box/faq/f036.html
- Box のファイルは、ゴミ箱で削除したり事業者を削除したりしない限り、税法上の保存期間に関係なく保存され続ける。有償プランを解約しても閲覧・ダウンロードはできる（MF FAQ。検索結果から確認、本文は未精読）。 https://biz.moneyforward.com/support/box/faq/save/f40.html 、 https://biz.moneyforward.com/support/box/faq/service/f003.html

[要確認]（実機テストで確かめる）
1. API でアップロードしたファイルにタイムスタンプが付くか（Box の画面で表示を確認）。付かない場合、スキャナ保存の真実性をどう担保するか。
2. 仕訳 ID を付けて API アップロードしたとき、区分が「スキャナ保存」になるか、「区分未設定」になるか。UI で変更が要るか。
3. API でアップロードしたファイルに解像度チェックが走るか。
4. 解約後、確定申告側の画面（仕訳と証憑の紐付けを見る画面）も見られるか。

### 2.3 freee 会計（ファイルボックス）

事実:
- API `POST /api/1/receipts`（multipart）で `receipt_metadatum_partner_name`／`_issue_date`／`_amount`（＝電帳法の検索項目）、`qualified_invoice`、`document_type` を渡せる。登録番号は OCR の結果が採用され、更新 API で上書きできる。応答の `origin` は `public_api`。**スキャナ／電子取引の区分を指定するフィールドは無い**。1 ファイル 64MB まで。
  出典: freee API スキーマ https://github.com/freee/freee-api-schema （v2020_06_15/open-api-3/api-schema.json）
- ファイルボックス: タイムスタンプ付与機能は 2022-01-17 に終了。変更履歴が管理されるので、タイムスタンプなしで要件を満たすと説明。改訂は全版を管理し、削除も履歴に残る。登録情報を変更できるのは保存日から 70 日以内（2 か月 + 7 営業日の考え方）。検索項目は「発行元・発行日・金額」。電帳法対応をしない場合は紙の原本を保存せよ、とある。**紙を廃棄する場合は、法定保存期間中アカウントと事業所を削除せず、ファイルボックス上で保存すること。ダウンロードしたファイル単体では履歴・検索などの要件を満たさない。** 個人のスターター・スタンダード・プレミアムが対象。
  出典: https://support.freee.co.jp/hc/ja/articles/4413886154649 （Zendesk API 経由で取得）

[要確認]
1. API でアップロードしたファイル（origin=public_api）が、スキャナ保存として扱われるか。電帳法対応の設定がどう適用されるか。
2. 解約後（無償状態）に、ファイルボックスの閲覧・検索・ダウンロードができるか。7 年分の課金が要るか。

### 2.4 自作ツール側の責任分界 [推測を含む]

| 要件 | 誰が満たすか | 自作側でやること |
|---|---|---|
| 解像度・階調（200dpi 相当・24bit） | **自作側**（MF の API は未達でも受け付ける） | 書類の寸法から必要な画素数を計算し、足りなければ撮り直しさせる。リサイズや不可逆の再圧縮で要件を割らない |
| 入力期限（7 営業日／2 か月 + 7 営業日） | **自作側**（期限内にアップロードを終える） | 撮影したらすぐアップロード（確認待ちのキューで止めない）。期限までの残りを表示し、超過を警告。超過したものは「紙保管」にフラグを立てる |
| タイムスタンプ／代替 | MF/freee（ベンダーのクラウド＝問32 の例外） | 自作サーバをタイムスタンプの代わりにしない |
| 訂正削除履歴 | MF/freee | アップロード後に画像を差し替えない（新しい版として扱う） |
| 検索項目（日付・金額・取引先） | 入力: **自作側** ／ 保持: MF/freee | freee はメタデータを API で渡す。MF は仕訳 ID を付けて紐付ける（または UI で入力） |
| 帳簿との相互関連性（重要書類） | MF/freee の紐付け機能 | 仕訳 ID と証憑 ID の対応を確実に作る |
| 見読性・ダウンロード対応 | MF/freee + 本人の PC | なし |
| システム概要書・事務手続書類 | **本人** | 自作ツールの概要書・操作手順書を書いて備え付ける（スキャナ保存の入力工程に自作プログラムが入るため **[推測]** 規則2②一イ・ロ が自作部分に及ぶ可能性あり → 税理士確認） |
| 規程（スキャナ電子化保存規程、各事務の処理規程、電子取引の訂正削除防止規程） | **本人** | 国税庁サンプルをもとに作る。freee 運用なら電子取引の訂正削除防止規程は必須（問43） |

自作側で原本を持ち続ける必要があるか:
- **法令上は不要 [推測]**。MF/freee 側が要件を満たした保存になっていれば、それが法定の保存。自作側の画像は控え。
- ただし、バックアップは法令上の要件ではないが「望まれる」（スキャナ 問20・問9）。MF/freee の障害や API 仕様の変更に備えて、オリジナルのファイル（撮影時のまま）・ハッシュ・メタデータ・アップロード日時・返ってきた ID を 7 年以上自作側にも残すのが妥当。
- 解約後の 7 年保存: ①MF/freee のアカウントを残す（第一選択）。②他サービスへ移す場合は、問64（タイムスタンプ代替データの移行には、移行データへのタイムスタンプ付与などが必要）と JIIMA の「データポータビリティガイドライン」に従う。個人では負担が大きい。電子取引データの移行は、事務処理規程で改ざん防止を担保できる（電子取引 問102）。

## 3. 青色申告特別控除

出典: タックスアンサー No.2072（令和8年4月1日現在） https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/2072.htm 、国税庁パンフ（令和8年8月） https://www.nta.go.jp/taxes/shiraberu/shinkoku/kojin_jigyo/0026007-003_02.pdf 、同（R8.4・簡易簿記向け） https://www.nta.go.jp/taxes/shiraberu/shinkoku/kojin_jigyo/0026004-012.pdf 、財務省 令和8年度改正大綱 https://www.mof.go.jp/tax_policy/tax_reform/outline/fy2026/08taikou_01.htm

**令和8年分まで（現行）**: 55 万円控除（正規の簿記、貸借対照表・損益計算書を添付、期限内申告）。加えて、e-Tax で送信するか、仕訳帳・総勘定元帳を優良な電子帳簿で保存して届出をすれば 65 万円。決算書をイメージデータで送信するのは不可。

**令和9年分から**:

| 控除額 | 要件 |
|---|---|
| 75 万円 | 65 万円の要件 + ①**優良な電子帳簿**（仕訳帳・総勘定元帳を課税期間の最初から）と届出、または ②**デジタルシームレス保存**と届出。届出の期限はその年分の確定申告期限 |
| 65 万円 | 正規の簿記 + **e-Tax で申告書と青色申告決算書（貸借対照表を含む）を期限内に送信** |
| 10 万円 | 書面申告など。簡易簿記で前々年の事業所得・不動産所得の収入が 1,000 万円超なら 0 円 |

- MF/freee で満たす形: 複式簿記は両ソフトとも可。e-Tax 送信も可（§4）。優良帳簿は両社とも JIIMA 電子帳簿認証あり → 「年初から優良設定で運用する + 届出 + e-Tax」で 75 万円を狙える **[要確認: 各ソフトの優良帳簿の設定方法、届出書の様式名が令和9年3月頃に変わる予定]**。
- 既に「優良な電子帳簿」で 65 万円控除の届出を出している人は、出し直し不要（R8.8 パンフ）。
- 注意: 自作側から API で仕訳を入れる場合も、訂正削除の履歴は MF/freee 側に残る **[推測]**。年末にまとめて入力すると優良帳簿の要件を満たせなくなる可能性がある、と弥生が案内している（二次情報） https://www.yayoi-kk.co.jp/lawinfo/detail.20260930/

## 4. 確定申告の提出経路

- **MF クラウド確定申告**: スマホアプリで電子申告（マイナンバーカード方式）できる。または xtx ファイルを出力して e-Tax ソフト（Web 版含む）で送る。 https://biz.moneyforward.com/support/tax-return/tax-return-guide/bs2/bs209.html 、 https://biz.moneyforward.com/support/tax-return/tax-return-guide/bs2/bs208.html
- **freee 会計（個人）**: 有料プランなら、freee の電子申告アプリ（スマホ・PC + カードリーダー）でマイナンバーカード方式の送信ができる。 https://support.freee.co.jp/hc/ja/articles/15111535603865
- **ID・パスワード方式**: 新規発行は令和7年10月1日に停止。令和9年分の確定申告からは使えなくなる予定。 https://www.e-tax.nta.go.jp/topics/2025/topics_20250925.htm
- **将来、自作に移る場合**: 国税庁の「確定申告書等作成コーナー」で、確定申告書と青色申告決算書（貸借対照表を含む）を作って e-Tax で送れる（R8.8 パンフに明記）。**集計値を手入力して送信しても、65 万円の e-Tax 要件は満たせる [推測: 要件は「データで送信」であり、作成手段は問われていない]**。ただし 75 万円を狙うなら、帳簿そのものを優良な電子帳簿として保存する必要があり、自作の帳簿システムで優良要件（訂正削除追加の履歴・相互関連性・検索）と JIIMA 相当の機能を自分で担保することになる → 難度が高い。

## 5. インボイス制度（簡易）

- **登録番号**: T + 13 桁。適格請求書（インボイス）側の記載事項。国税庁の公表サイト（Web-API あり）で照会できる。 https://www.invoice-kohyo.nta.go.jp/
- **原則課税の帳簿記載事項**: 相手方の氏名・名称、取引年月日、取引内容（軽減税率対象ならその旨）、対価の額。帳簿への登録番号の記載は要件として挙がっていない **[要確認: インボイス Q&A の該当問を精読していない]**。 https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/pdf/qa/01-14.pdf
- **免税事業者**: 仕入税額控除が無いので、消費税上のインボイス保存義務は無い。所得税（青色）の帳簿・書類保存は必要。
- **2割特例**: 令和8年9月30日を含む課税期間まで。個人は**令和8年分が最後**。 https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/invoice_2tokurei.htm
- **3割特例（令和8年度改正）**: インボイス登録で課税事業者になった個人は、令和9年分・令和10年分に適用できる。 https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/invoice-review/index.htm 、 https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/invoice-review/pdf/0026002-095.pdf
- **2割・3割特例と簡易課税**: 売上の税額から納付税額を計算するので、仕入税額控除のためのインボイス保存は計算上不要（NTA 2割特例ページ）。所得税上の領収書保存は残る。
- **原則課税**: 仕入税額控除にはインボイスと帳簿の保存が要る。保存期間は 7 年。
  - 免税事業者等からの仕入れの経過措置: 80%（〜令和8年9月30日）→ **70%（令和8年10月1日〜令和10年9月30日）** → 50% → 30%（〜令和13年9月）。帳簿に「経過措置の適用を受ける旨」の記載が必要。 https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/pdf/qa/01-15.pdf
  - 少額特例: 基準期間の課税売上高 1 億円以下などの事業者は、1 万円未満の課税仕入れでインボイス保存が不要（令和11年9月30日まで）。 https://www.nta.go.jp/publication/pamph/shohi/kaisei/202304/02.htm
- **[推測]** 将来、課税方式が変わっても困らないように、免税・2割/3割・簡易課税のどれでも、登録番号・適格かどうか・税率区分・税込額は最初から記録しておくのが安い。

## 7. 自作側が満たすべき要件チェックリスト（実装要件）

**撮影・取り込み**
- [ ] R1: 撮影時に書類の種類（紙＝スキャナ保存／電子データ＝電子取引）を必ず選ばせる。電子データを印刷・撮影したものをスキャナ保存として扱わない。
- [ ] R2: 書類の縦横の寸法（mm。プリセット: A4・レシート幅 58/80mm など）から、必要な画素数を「寸法 mm ÷ 25.4 × 200」で縦横それぞれ計算し、満たさない画像は拒否または再撮影を促す。
- [ ] R3: 24bit カラー（RGB 各 8bit）で保存する。重要書類はグレースケールにしない。
- [ ] R4: 撮影したオリジナルのファイルを、そのままのバイト列で保存する（sha256 を記録）。送信用に縮小や再エンコードをする場合も、R2・R3 を満たし、非圧縮・可逆圧縮か高品質 JPEG にする。MF の 5MB 制限を超える場合の扱いを決める（仕様の未決事項）。
- [ ] R5: 受領日（書類の日付ではなく、受け取った日）を記録する。初期値は撮影日。

**期限管理**
- [ ] R6: 受領日から「7 営業日」（規程を採るなら「2 か月 + 7 営業日」）の期限を計算して表示する。営業日カレンダーを持つ。
- [ ] R7: **撮影直後に MF/freee へアップロードする（OCR・分類・人の確認を待たない）**。失敗したら再試行し、期限の 2 営業日前に警告する。
- [ ] R8: 期限超過のものは「紙原本の保管が必要」フラグを立て、廃棄させない。
- [ ] R9: 「紙廃棄 OK」は、アップロード成功 + 同等確認（画面で欠け・折れを確認したチェック）+ 期限内、の3条件を満たしたときだけ表示する。

**検索項目・紐付け**
- [ ] R10: 取引年月日・取引金額（税込、または帳簿の経理方式に合わせる）・取引先を、人の確認で確定させる。OCR の値だけで確定しない。
- [ ] R11: freee: `receipt_metadatum_*` に R10 の値を渡す（または更新 API で後から入れる。保存から 70 日以内）。
- [ ] R12: MF: 仕訳を登録したあと、`journal_id` 付きで証憑をアップロードする（または既存の証憑を紐付ける）。仕訳 ID なしで終わらせない。取引先を仕訳の摘要または取引先項目に必ず入れる。
- [ ] R13: 仕訳 ID ⇔ 証憑 ID ⇔ 自作側 ID の対応表を持つ（相互関連性の補強と監査用）。

**改ざん防止・履歴**
- [ ] R14: アップロード後は、自作側で画像を上書きしない。修正は新しい版として送り、旧版を残す。
- [ ] R15: 自作側の操作ログ（誰が・いつ・何を変えたか）を追記専用で持つ。

**インボイス**
- [ ] R16: 登録番号（`^T\d{13}$`）、適格かどうか、税率区分（10%・8%）、税率ごとの税額を記録する。可能なら国税庁の公表サイト Web-API で照会した結果と照会日時を残す。
- [ ] R17: 経過措置（80/70/50/30%）の対象かどうかと、少額特例の対象かどうか（1 万円未満）をフラグで持つ（原則課税に移ったときに使う）。

**保存・持ち出し**
- [ ] R18: 自作側のバックアップに、オリジナルのファイル・ハッシュ・メタデータ・アップロード日時・外部 ID を、年分の翌年 3/16 から 7 年以上保持する（削除ジョブは手動承認制）。
- [ ] R19: MF/freee から、年分ごとに証憑と仕訳を一括エクスポートする手順を用意する（解約や障害への備え。ただし法定の保存はアカウント側）。

**書類（コードではなく本人が用意するもの）**
