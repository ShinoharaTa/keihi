## 1. 結論の要約

1. **法令**: 法定の保存先を MF または freee に置く構成は成立し得る（両社とも JIIMA のスキャナ保存・電子取引・電子帳簿認証を取得済み）。ただし入力期限・規程・検索項目入力は利用者側の責任。出典と根拠は legal.md §0〜§2。
2. **青色申告**: MF/freee から e-Tax 送信で 65 万円控除の要件を満たす。令和9年分からは 75 / 65 / 10 万円の3段階（legal.md §3）。
3. **Kev**: 実在するが（jaredpalmer/kev, Apache-2.0）、0.8B は英語のみ・x86 CPU は公式サポート外。N100 では 1 件 10〜60 秒（推定）、メモリピーク約 7GB。**MVP では使わず、辞書 → Gemini（科目を選択肢から選ばせる構造化出力）→ 確定分を辞書に学習** を推す（classification-ocr.md §A）。arjun988/Kev は重みを持たない別物。
4. **OCR**: 「Gemini 3.8 Flash Lite」は存在しない（3.8 の Lite は TTS 専用）。**Gemini 3.5 Flash-Lite の有料 tier** を推奨。無料枠は学習利用・人による閲覧ありで不可。有料でも不正監視のログが 55 日残り、ゼロにするなら Vertex AI。医療など機微なものだけローカル（PaddleOCR PP-OCRv6）に回す選択肢あり。YomiToku は個人事業の経理でも有償ライセンスが要る。
5. **スコープ推薦**: 入口自作 → 会計サービスへ送信。原本は自前でも追記専用で 7 年以上保管（Backblaze B2 の Object Lock へ restic で暗号化バックアップ。月数十円程度）。

## 2. ドラフト間の食い違いと統合後の整理

architecture.md は法令調査より前に書いたため、以下は本節を優先する。

| 論点 | architecture.md | 統合後 |
|---|---|---|
| 正本の置き場所 | 自前ローカルが正本 | **法定の保存先は MF/freee**。自前のサーバーはタイムスタンプの代わりにならない（一問一答 スキャナ 問32）。自前保管は控え・バックアップとして残す |
| 証憑を送るタイミング | 人が確認 → 仕訳作成 → 証憑を送る | スキャナ保存には入力期限（おおむね 7 営業日、規程を作れば最長 2 か月＋7 営業日）がある。**撮影したらすぐ送り、分類・確認は後で** |
| 5MB 上限のための縮小（MF） | 縮小した派生ファイルを送る | 解像度・階調の要件（200dpi 相当・24bit カラー）を割らない範囲に限る。不可逆の再圧縮が許されるかは税理士確認 |
| 分類のフォールバック | 辞書 → Kev | 辞書 → Gemini（上記 §1-3） |

### 重要: MF と freee で法令面の扱いやすさが違う
- **MF**: 仕訳 ID を付けずに API で上げた証憑は「電子取引データ保存」扱いになると公式に書かれている。紙の領収書をスキャナ保存として扱うには、送る時点で仕訳が必要。しかし仕訳は確認後にしか作れない。この順序の矛盾と、API で上げたときにタイムスタンプが付くかどうかは実機テストが要る。日付・金額・取引先は API で渡せず、証憑の削除とダウンロードの API も無い。
- **freee**: `POST /api/1/receipts` で発行元・発行日・金額（検索項目）を渡して**先に証憑だけ送れる**。仕訳（取引）は後から紐付ける。法令が求める「即アップロード → 後で確認」の順序とそのまま合う。真実性はタイムスタンプではなく変更履歴で担保する方式なので、電子取引の訂正削除防止規程が必須（問43）。証憑は API でダウンロードできる。
- 現時点の材料では、**証憑保管の観点では freee の方が素直**。MF を使う場合は、API で上げた証憑の区分とタイムスタンプを PoC で確認するのが前提。

## 3.0 ユーザー回答（2026-10-13）
- 会計サービス: **現在は MF を使用中、freee への移行も検討**。→ 送信先は Provider で抽象化する（architecture.md Q9 は「抽象化を残す」で決定）。移行する場合も、MF 側に保存した過去分の証憑は保存期間中アカウントを残して保持する（legal.md §0-6）。移行するなら年の区切りで行う想定
- OCR: **Gemini 3.8 Flash（有料 tier）**。料金は 2026-12-31 まで入力 $0.75 / 出力 $3.75 per 1M、2027-01-01 から倍（classification-ocr.md §B-1）。月 100 枚なら数十〜百円程度の見込み（推定）
- MF の契約: **Web 版パーソナルミニ**（2026-10-17 回答）。当面 MF を継続し、PoC で API の可否を確認（plans-comparison.md の推薦どおり）。Box の累計 1,000 件上限に近づいたらパーソナルへ
- PoC は本人の本番アカウントで行ってよい（別事業者なし）。目的は「MF/freee を帳票の保存先にしつつ、経費精算・確定申告を自動化」。入出金明細を自然言語で振り分けたい（2026-10-17）→ transactions.md
- **自然言語の指示は keihi に実装しない**（2026-10-17）。ユーザー自身のエージェント（Self agent）から操作するため、keihi は **MCP サーバー / freee API のプロキシ**を提供する方針。transactions.md の U10・M7、freee-codex.md の Codex 連携（`codex exec`）は不採用。M8 の「keihi MCP」を中核に格上げ。**エージェントは同じサーバー上で動き、MCP は 127.0.0.1 のみ。書き込みは「エージェントが提案 → PWA の確認カードで本人が確定 → keihi が freee に書き込む」**
- 会計サービス: **freee スタンダードへ切り替える（Y1 承認）**。帳簿は 2027-01-01 から。PoC は無料の開発用テスト事業所で先に行い、年払い契約は 12 月。2026 年分は MF で申告
- 実行形態: **サーバー（Tailscale 内のみ）+ PWA**。ネイティブアプリは作らない
- 確認 UI: **Gemini と必要に応じて対話でき、科目などは画面上で選べる。A2UI の概念を取り込む** → 設計は a2ui-review-ui.md（**B 案で決定**。U2 自由文での AI 相談は MVP に入れない。U6 AI ログ・応答原文の保存は 7 年）
- スマホ: **iOS / Android の両方に対応**。PWA のカメラ撮影は両 OS で動く。共有シートは Android が Web Share Target、iOS がショートカットで POST（architecture.md §3.1）
