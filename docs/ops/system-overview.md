# keihi システム概要書（下書き）

> **下書き。税理士の確認が必要。** 電子帳簿保存法のシステム概要書（規則 2 条 2 項 1 号イ、2 条 6 項 6 号。legal.md §1.2・§1.3）として
> 本人が備え付ける文書の下書き。自作部分（keihi）について概要書が要るかは税理士確認 #2（legal.md §6）。要らなくても運用の記録として残す。
> 版: 0.1（2026-10-17）。改訂したら末尾の改訂履歴に書く。

## 1. 目的と範囲

- 事業者（個人・青色）が受け取った領収書・請求書等を、**freee 会計のファイルボックス**に期限内に保存し、取引（帳簿）と紐付けるための入口のツール。
- **法定の保存先は freee のファイルボックス**（訂正・削除の履歴で真実性を担保。freee-codex.md §2.5）。keihi 側の原本とバックアップは控え。
- 対象: 2027 年分以降（2027-01-01 から運用。2026 年分は従来どおり MF で処理し、keihi は扱わない）。
- 担当: 事業者本人（1 名）。作業担当者・管理責任者を兼ねる。

## 2. 構成

| 部分 | 内容 | 場所 |
|---|---|---|
| サーバー | 自宅の常時稼働の Linux 機（Ubuntu 24.04）。keihi は利用者 `shino3` の systemd --user で動く | 本人の管理 |
| 取り込み（PWA） | スマートフォンのブラウザ（PWA）。撮影・共有・書類の種類（紙 / 電子データ）の選択 | Tailscale 経由でだけ届く。127.0.0.1:8795 |
| 原本ストア | 受け取ったバイト列をそのまま保存（sha256 の名前、上書き・削除の機能なし、0444） | `~/.local/share/keihi/objects/` |
| DB | SQLite。書類・抽出・確認・送信の状態・監査ログ（ハッシュチェーン、追記専用） | `~/.local/share/keihi/keihi.db` |
| worker | 即アップロード・OCR・取引の送信・照合を行う一時プロセス | systemd --user |
| freee 会計 | ファイルボックス（証憑の法定の保存）、取引（帳簿） | freee スタンダード |
| Gemini API | OCR と科目の候補（有料 tier の専用プロジェクト） | Google |
| バックアップ | restic で暗号化し、オフサイトに追記のみ（docs/ops/backup.md） | 保存先は Q4（既定案 B2 + Object Lock） |
| keihi MCP（M7） | 同じ機械のエージェントからの読み取りと**提案**の受け口（127.0.0.1:8796） | M7 以降 |

## 3. 処理の流れ

```
撮影・共有 ─▶ 1 取り込み ─▶ 2 原本保存 ─▶ 3 即アップロード（freee ファイルボックス）
                                         │
                                         ├▶ 4 OCR・科目の候補（Gemini）
                                         │      ▼
                                         │  5 本人の確認・確定（PWA）◀── （M7）エージェントの提案
                                         │      ▼
                                         └▶ 6 検索項目の登録（freee。保存から 70 日以内）
                                                ▼
                                            7 取引の作成と証憑の紐付け（freee）
                                                ▼
                                            8 照合（日次）・証憑の照合（月次）・バックアップ（日次）
```

1. **取り込み**: PWA で書類の種類（紙＝スキャナ保存 / 電子データ＝電子取引）を必ず選ぶ（R1）。紙は書類の寸法から必要な画素数
   （200dpi 相当）を確かめ、足りなければ撮り直す（R2）。24bit カラー（R3）。受領日を記録する（初期値は撮影日。R5）。
2. **原本保存**: 受け取ったバイト列を加工せずに保存し、sha256 を記録する（R4）。以後、keihi は原本を上書きしない（R14）。
3. **即アップロード**: 確認を待たずに、原本をそのまま freee のファイルボックスへ送る（R7）。入力期限（受領から 7 営業日。
   規程で業務処理サイクル方式を採るなら 2 か月 + 7 営業日。R6）の 2 営業日前を過ぎても送れなければ要対応にする。
   期限を過ぎたものは紙原本の保管を要とする（R8）。紙の廃棄は「アップロード成功 + 同等確認 + 期限内」のときだけ（R9）。
4. **OCR・科目の候補**: Gemini が日付・金額・取引先・登録番号・税率ごとの金額と、科目の候補を出す。**候補であって確定ではない**。
5. **確認・確定**: 本人が PWA で値を確かめて確定する。OCR やエージェントの値だけでは確定しない（R10）。確定の内容は版として追記する。
6. **検索項目の登録**: 確定した取引年月日・金額・取引先を、freee の証憑のメタデータに入れる（R11。保存から 70 日以内）。
7. **取引の作成**: 支出の取引を作り（連携カード払いは未決済とし freee 側で明細と消込、現金・事業主借は決済済み）、証憑を紐付ける（帳簿との相互関連性。R13 の対応表を keihi 側にも持つ）。
8. **照合**: 日次で freee の取引を読み直し、金額・科目・証憑の紐付けが変わっていないか確かめる。月 1 回、上げた証憑をダウンロードして
   手元の原本と比べる（T5-6）。差があれば要対応として本人に見せる（自動で直さない）。

### 3.1 エージェント（keihi MCP、M7）の位置づけ

- エージェント（同じ機械で動く AI のクライアント）は、keihi の**読み取りと「提案」の作成だけ**ができる。
- **エージェントは提案だけ。確定は必ず本人が PWA で行い、freee への書き込みは keihi 本体が行う。** エージェントは freee のトークンを持たず、freee に直接書かない。
- エージェントは、証憑の削除・差し替え、検索項目の 70 日の期限を過ぎる変更、keihi が作っていない取引の削除を提案できない。
- 入力期限の処理（工程 1〜3）は keihi 本体だけが行い、エージェント（MCP）は関わらない。MCP が止まっても期限の処理は止まらない。
- エージェントの提案から確定した値は、確認の記録に「出所: agent」として残す（mcp.md §7）。

## 4. 真実性・可視性の確保（担当の分け方。legal.md §2.4）

| 要件 | 担当 | keihi 側でしていること |
|---|---|---|
| 入力期間 | keihi | 即アップロード、期限の表示と警告、紙原本の保管フラグ |
| 解像度・階調 | keihi | 取り込み時の検査。リサイズ・再圧縮をしない |
| タイムスタンプ / 代替 | freee | なし（keihi をタイムスタンプの代わりにしない） |
| 訂正・削除の履歴 | freee | アップロード後に差し替えない。直すときは新しい版として送る |
| 検索項目 | 入力 keihi / 保持 freee | 確定した値をメタデータとして送る |
| 帳簿との相互関連性 | freee | 取引に証憑を紐付ける。keihi 側にも対応表 |
| 見読性・ダウンロード | freee + 本人の PC | なし |
| 電子取引の真実性 | 本人 | 「電子取引データの訂正及び削除の防止に関する事務処理規程」（templates/） |

## 5. 記録と保全

- 操作の記録: keihi の監査ログ（誰が・いつ・何を）。各行が直前の行のハッシュを持ち、改ざんを検出できる。追記のみ（R15）。
- バックアップ: 日次で暗号化してオフサイトへ（追記のみ）。四半期にリストア訓練（docs/ops/backup.md、restore-drill.md）。
- 保持: keihi 側は一律 8 年（受領日の年分の翌年 3/16 から。docs/ops/retention.md）。期間を過ぎても自動では消さない。
- シークレット: `~/.config/keihi/secrets.env`（0600）。freee のトークンは別ファイルで、バックアップに含めない。
