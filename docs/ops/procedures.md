# 事務処理の手順書（下書き）

> **下書き。税理士の確認が必要。** 電子帳簿保存法の「手順と担当を示した書類」（legal.md §1.2 のシステム概要書等、R21）として
> 本人が備え付ける文書の下書き。担当はすべて事業者本人。システムの全体は [system-overview.md](system-overview.md)。
> 版: 0.1（2026-10-17）。

## 1. 書類を受け取ったとき（随時）

| # | 手順 | 期限・注意 |
|---|---|---|
| 1 | 紙の書類: PWA で「紙」を選び、書類の寸法を選んで撮影する。画素数が足りないと出たら撮り直す | 受領から 7 営業日以内（早期入力方式）。撮ったらその場で |
| 2 | 電子データ（メールの PDF・EC の領収書）: PWA の共有か取り込みで「電子データ」を選ぶ。**印刷して撮影しない** | 受け取ったら速やかに |
| 3 | 受領日が撮影日と違うときは直す | |
| 4 | 紙の書類は、画面で欠け・折れ・裏面の記載がないことを確かめる（同等確認） | |
| 5 | アップロードが終わったこと（「freee に保存済み」）を確かめる | 失敗の表示が出たら §6 |
| 6 | 紙の原本: 「紙廃棄 OK」が出たものだけ廃棄してよい。「紙原本の保管が必要」が出たものは保管箱へ | 税理士確認 #1・#4 の回答が無い間は、**全件を保管**する |

## 2. 確認と確定（週に 1 回以上）

1. PWA の確認待ちを開き、OCR の値（日付・金額・取引先・登録番号・税率ごとの金額）と科目を確かめ、違えば直して確定する。
   AI やエージェントの値をそのまま確定しない。
2. 確定すると keihi が freee に検索項目を入れ、取引を作って証憑を紐付ける。**検索項目は保存から 70 日以内**に入れる必要があるので、確認待ちを溜めない。
3. 私用・重複・対象外は、その旨を選んで確定する（削除しない）。
4. （M7 以降）エージェントの提案は、PWA の「提案」で内容を見て、本人が確定するか却下する。エージェントに確定させない。

## 3. 要対応（随時。PWA の帯とバッジ）

| 表示 | すること |
|---|---|
| アップロードの期限が近い / 失敗 | 通信・freee の状態を確かめ、再送。期限を過ぎたら紙原本を保管 |
| freee の再認可が必要 | `node src/cli/keihi.ts freee auth` |
| freee 側の取引が変わった・証憑が外れた | freee で内容を確かめ、正しい方に合わせる（keihi は自動で直さない） |
| 証憑の照合で不一致（remote_sha256_mismatch 等） | freee のファイルボックスで該当の証憑を開き、内容と履歴を確かめる。経緯を §8 の記録に残す |

## 4. 定期の確認

| 頻度 | すること |
|---|---|
| 毎週 | バックアップの結果（docs/ops/backup.md §6）。3 日以上失敗が続いていれば原因を直す |
| 毎月 | 証憑の照合の結果（audit の `backup.remote_verify`）。紙原本の保管箱を月別に整理 |
| 四半期（1/4/7/10 月） | リストア訓練の結果（docs/ops/restore-drill.md）を §8 に記録 |
| 毎年 1 月 | 前年分の書き出し（§5）。規程・本書・概要書の見直し |
| 2027-10 | freee の JIIMA 認証の更新を確認 |

## 5. 年次の書き出し（R19。毎年 1〜3 月、申告の前後）

法定の保存は freee 側。解約・障害への備えとして、年分ごとに書き出して keihi の原本とは別の場所に置く。

1. freee の画面から仕訳帳・総勘定元帳を書き出す（CSV / PDF）。
2. 証憑は freee の API（`GET /receipts/{id}/download`）でダウンロードできる。keihi の対応表（`remote_receipt_id, remote_deal_id`。T4-7）の
   エクスポートと一緒に保存する。件数が多いときは 1 秒 3 回・1 日の予算に注意し、数日に分ける。
3. 書き出したものの一覧（件数・sha256）を作り、§8 に記録する。
4. 書き出したファイル単体では電帳法の要件（履歴・検索）を満たさない。**freee の契約と事業所は保存期間中は残す**。

## 6. 障害のとき

| 状況 | 手順 |
|---|---|
| keihi が動かない | `systemctl --user status keihi-web`、`journalctl --user -u keihi-web`。直るまでの書類は、紙なら保管し、電子データは受け取ったまま保存しておき、復旧後すぐ取り込む。期限が迫るものは freee のアプリ・画面から直接アップロードし、§8 に記録 |
| サーバーの故障 | docs/ops/restore-drill.md §2 の手順で復元 |
| freee の障害 | 復旧を待って再送（keihi が自動で再試行）。期限を過ぎたものは紙原本を保管 |
| シークレットの漏えい・紛失 | docs/ops/restore-drill.md §4 の手順で再発行 |

## 7. 訂正・削除

- 保存した証憑（freee のファイルボックス・keihi の原本）は、原則として訂正・削除しない（規程の下書き: templates/）。
- やむを得ず訂正・削除するときは、freee の画面で行い（履歴が残る）、規程の「取引情報訂正・削除申請書」の項目を §8 の記録に書く。
- keihi の原本は消さない。確定の誤りは、新しい版の確定として記録する。
